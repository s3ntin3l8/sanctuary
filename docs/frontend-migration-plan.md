# Plan: Sanctuary frontend → React + Vite + TypeScript SPA (per "Sanctuary Prototype")

## Context

The frontend today is Jinja + HTMX + Alpine: 123 templates (12.2k lines), ~2,000 lines of
untyped first-party JS as globals, ~480 lines of inline scripts, no bundler, no JS lint, no
types. 130 of 157 endpoints return HTML fragments; there are no Pydantic response models.
The Claude Design prototype (`Sanctuary Prototype.dc.html`, React 18 runtime, one 1,700-line
component with mock data) redesigns the app around a denser shell, a bundle-centred triage,
a full-screen document HUD with an intelligence rail, a Home briefing, a command palette and
a restructured Settings.

Decisions already made by the user: **full SPA, cut over view by view**, **React + Vite**.

Outcome: a typed `frontend/` SPA talking to a typed JSON API (`/api/v1`), with Jinja, HTMX,
Alpine and all HTML-fragment routes deleted. Per CLAUDE.md "clean as you go", each cutover
PR deletes the templates, routes, JS and HTML tests it supersedes. No shims.

## Assumptions (correct these at approval if wrong)

1. **Views the prototype does not draw are ported in the new visual language, not dropped:**
   Chat, Costs page, Contacts (sender detail), Slicing review, pins, login/signup, admin
   users, case sharing, truth map, timeline, toasts, empty/loading/error states.
2. **The existing swim-lane graph keeps its capability** (computed layout, edges, pan/zoom).
   The prototype's graph is a static mock; only its node/lane styling is adopted.
3. **Scope is the frontend plus the JSON API it needs.** Prototype features with no backend
   today are not faked in the UI. Each phase starts with a gap check and files a tracked
   issue per missing backend capability. Likely candidates: AI morning briefing, activity
   feed, per-field metadata confidence, AI draft-case creation, endpoints-plus-roles AI
   config, Chandra OCR engine choice, relationship confirm/reject, summary approve, archive.
4. Privacy-first holds: all fonts self-hosted (add JetBrains Mono), no CDN scripts, no
   Google Fonts. Dark-only hard-coded colours in the prototype become tokens with light values.

## Target architecture

**Frontend (`frontend/`, replaces root `package.json`)**
- Vite, React 19, TypeScript `strict`, React Router (data router), TanStack Query,
  Tailwind v4 via `@tailwindcss/vite`. ESLint + Prettier. Vitest + Testing Library.
- `src/styles/tokens.css`: prototype tokens (`--bg --rail --panel --panel2 --card --card2
  --aibg --line --line2 --line3 --ink --ink2 --muted --muted2 --tealink --accent --on-accent
  --logo`) under `[data-theme]`, exposed through `@theme`; add semantic tokens the prototype
  hard-codes (originator court/opposing/own/third, critical, success, warning, graph and
  reader surfaces). Replaces the Material-3 names in `static/input.css`.
- `src/ui/`: primitives lifted from the prototype's style builders: Button, IconButton,
  Chip, Badge, Tabs, SegmentedControl, Checkbox/Radio/Toggle, Input/Select, Card, DataGrid
  row, Popover/Menu, Tooltip, Modal + ConfirmDialog, Toast, PipelineBar, DatePicker, Avatar.
- `src/shell/`: 56px IconRail (Home, Triage, Cases, theme, search, processing popover,
  profile menu), CommandPalette (⌘K), ProcessingQueue modal, IngestModal, shortcuts.
- `src/features/<view>/`: one folder per view; `src/features/doc/DocIntelligence.tsx` is
  shared by the triage inline review and the HUD rail (the prototype duplicates this markup).
- `src/api/`: `schema.d.ts` generated by `openapi-typescript` from `/openapi.json`, a thin
  typed `fetch` client (`credentials: 'same-origin'`, 401 → `/login`), query hooks.
- Polling (`hx-trigger="every Ns"` today) becomes TanStack Query `refetchInterval` that
  stops on terminal status. Chat streaming ports `static/js/chat.js` (fetch reader over
  `data:` frames) to a typed hook.

**Backend (`app/api/v1/`)**
- New JSON routers with Pydantic response models in `app/schemas/` (DTOs; ORM objects stop
  leaking into views). Reuse existing services unchanged: `HomeService.get_home_data`,
  `CaseService.get_all_cases_directory_paginated`, `CaseDashboardService.build_context`,
  `CaseGraphService.build_payload` (`GraphPayload` is already primitives),
  `CaseTimelineService.build_payload`, `ClaimService.get_truth_map`, `build_hud_context`
  (`app/services/hud_context.py`), `get_triage_bundles` / `get_triage_filter_options`,
  `CostService`, `build_role_cards`, `stream_answer`.
- Authorization: every v1 route uses the existing `app/api/access_guards.py` dependencies.
  Object IDs stay in the **path**, because `require_triage_object_owner` only reads
  path/query/form and would silently skip IDs in a JSON body. Add a test that proves it.
- Close the admin gap in v1: maintenance, AI settings and export require
  `get_current_admin`; export is user-scoped. File an issue for the legacy routes until
  their phase deletes them.
- Errors: `/api/*` gets JSON 404/422/500 (`{detail, code}`) instead of HTML error templates.
- Auth: keep the signed `session` cookie and `OriginGuardMiddleware`. Add
  `POST /api/v1/auth/login|logout|signup`, `GET /api/v1/me`. OIDC redirects unchanged.
- Document body: keep `render_highlighted` server-side (offset splicing stays in Python);
  v1 returns `body_html` with `data-passage-id` on each `<mark>` plus a `passages[]` list.
  React renders it and wires click-to-sync and pin anchors by passage id.
- Serving: FastAPI mounts `frontend/dist/assets` (hashed, long cache) and serves
  `index.html` for SPA-owned paths, listed in one `SPA_ROUTES` tuple in `app/main.py`.
  A cutover moves a path from its Jinja handler into that tuple. Links from the SPA to
  not-yet-migrated views are plain full-page anchors.
- Dev: `vite` on 5173 proxying `/api`, `/auth`, `/static` and legacy paths to 8000 with
  `changeOrigin: false`, so `Host` and `Origin` both stay `localhost:5173` and
  `_same_origin` (`app/main.py:184`) passes without weakening the guard.

**Tooling**
- Makefile: `make setup` runs `npm ci` in `frontend/`; `make run` also starts Vite;
  `make frontend-build`, `make frontend-test`, `make api-types`; `make lint` adds
  eslint + `tsc --noEmit`.
- CI (`.github/workflows/ci.yml`): Node job with typecheck, eslint, vitest, build, and an
  API-types drift check (regenerate `schema.d.ts`, fail on diff). E2E job builds the SPA
  before starting uvicorn.
- Dockerfile: the `css-builder` stage becomes `frontend-builder` (`npm ci && npm run build`),
  final image copies `frontend/dist`.
- Commit the prototype to `docs/design/` as the visual reference.

## Risks to watch

- Hybrid period looks inconsistent (old and new shell side by side). Phases 0–5 are ordered
  so the daily path (Home → Triage → HUD → Case) converts first.
- Coverage floor (65%) may dip when HTML tests are deleted; replace tests in the same PR.
- `static/js/slicing.js` is shadowed by a second `slicingGrid` in `alpine-utils.js`; port
  from the `alpine-utils.js` version (the one that actually runs) in phase 3.
- Stale e2e `test_navigation_to_contacts` (no `/contacts` link exists): fix in phase 1.

## Verification

- Per PR: `make lint`, `make test`, `make frontend-test`, `make frontend-build`,
  `make api-types` with no diff, `make test-e2e-isolated`.
- Manual per view: `make run`, open the view on `localhost:5173` beside the prototype in
  both themes; exercise every mutation and confirm no 403 from the origin guard; confirm
  polling stops on completion; confirm a second user gets 403/404 on another user's objects.
- Phase 7: `grep -rE "hx-|x-data|TemplateResponse|HX-" app static` returns nothing; Docker
  image builds and serves the SPA; login, ingest → triage confirm → HUD → case graph → chat
  works end to end against seeded data.
